## OpenConnect v0.45.0: the server reads HRV, Pulse Ox, respiration and body composition

The server catches up with the Health API: the four data types that were still marked *planned* now land in the
database, in the JSON API and on the *Health* page.

### Install

Download `openconnect-v0.45.0.apk` below and open it. It installs **over v0.44.0 and keeps your data and your keys**
(same signing key). Needs Android 8.0 or newer. Check the download against `openconnect-v0.45.0.apk.sha256`.
The server is installed as before (`pip install -e ".[dev]"`, or `docker compose up --build`); the SQLite file gains
one table and needs no manual migration.

### What is new

- **Nightly HRV, Pulse Ox and respiration.** The server now pulls `hrv`, `pulseox` and `allDayRespiration` next to the
  daily summaries, sleep and stress it already read. For each day it keeps the **HRV average of the night**, the weekly
  average and Garmin's own status word (*balanced*, *low*, …); the **average and lowest SpO2 reading**; and the
  **average, lowest and highest breathing rate**. Because every type arrives as its own summary, they are merged into
  the day field by field: a daily that arrives later, or a re-sync of the same day, no longer wipes what another
  summary already filled in.
- **Body composition.** `bodyComps` is stored **per measurement**, not per day, so several weigh-ins on one day all
  survive: weight, body fat, BMI, muscle mass, body water, bone mass, visceral fat and basal metabolic rate, with the
  device name when Garmin sends one.
- **On the *Health* page.** Four new tiles with sparklines (HRV, Pulse Ox, respiration, weight), a **Vital signs** table
  for the last 30 days and a **Body composition** table for the last 90 days.
- **In the API.** `GET /api/health/vitals` and `GET /api/health/body-composition`, both with `start` and `end`; the new
  daily fields also appear in `GET /api/health/daily`. Sync and webhook responses now count `hrv`, `respiration`,
  `pulseox` and `body_comps` per run.
- **In the demo.** The offline Garmin source generates all four types, so mock mode fills the new page without
  credentials.

### Not verified

- **Nothing here ran against a real Garmin account.** The endpoint names and field names follow Garmin's Health API
  documentation, and a data type the account has not granted is skipped as before (HTTP 403), but the four payloads
  have not been seen live. Treat the exact field names as *verify* until a sync with real credentials has been looked
  at.
- **No phone was involved.** This release changes the server only; the APK is a new build so its version matches the
  tag, not a change to the app.
- The HRV status is Garmin's own word, shown as sent; OpenConnect does not reinterpret it.

### What changed in the code

- `domain.py`: `DailySummary` gains the HRV, SpO2 and respiration fields plus `has_vitals`; new `BodyComposition`.
- `storage/db.py`: `body_compositions` table. `storage/repository.py`: `upsert_body_composition`,
  `list_body_compositions`, `latest_body_composition`.
- `garmin/mapper.py`: `map_hrv`, `map_pulse_ox`, `map_respiration`, `map_body_composition` (tolerant of missing fields
  and Garmin's -1 "not measured" markers; grams to kilograms; prefers Garmin's own respiration averages when present).
- `garmin/ingest.py`: one `apply_day_patch` path for every per-day summary, `DAILY_PATCH_FIELDS` for the merge, and
  per-type counters in `IngestResult`.
- `garmin/client.py` and `garmin/fake.py`: the four new pull kinds, and deterministic demo data for them.
- `services/dashboard.py`: vitals in the trend series and three new weekly averages.
- `web/routes_api.py`, `web/routes_ui.py`, `web/templates/health.html`: the endpoints, context and page sections.
- Tests: mapper, storage, ingest (including arrival-order and re-ingest), fake, API and UI for the new types.
- Version 0.45.0, versionCode 45.
