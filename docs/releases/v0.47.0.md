## OpenConnect v0.47.0: the last roadmap items

The remaining items from the roadmap are in: activities through your own key, Ping/Pull callbacks, optional
sign-in and the two health types that had no fixed layout.

### Install

Download `openconnect-v0.47.0.apk` below and open it. It installs **over v0.46.0 and keeps your data and your keys**
(same signing key). Needs Android 8.0 or newer. Check the download against `openconnect-v0.47.0.apk.sha256`.
The server is installed as before; no schema change is needed for this release.

### What is new

- **Activities with a personal key.** `PersonalApiSource` now pages through the account's activity list, downloads
  each ZIP, extracts the FIT file and imports it with the same importer used for uploads. The activity keeps the
  account's id and name and gains a real track, splits and best efforts. Only the 30 newest activities are fetched
  per sync; a failed or missing file falls back to the activity summary.
- **Ping/Pull callbacks.** A push notification with a `callbackURL` is now followed: the URL must be HTTPS and its
  host must be on `OPENCONNECT_CALLBACK_HOSTS` (default `apis.garmin.com`). Redirects are not followed, responses are
  capped at 5 MB, and the result is ingested through the same path as any other push. The webhook response reports
  `callbacks_followed` and `callback_errors`; a rejected or broken callback never fails the whole webhook.
- **Optional sign-in.** Set `OPENCONNECT_PASSWORD` to require a password for every page and API. The session is a
  signed, seven-day, HTTP-only cookie bound to that password; no session table is kept and a restart does not log
  you out. `/healthz` and static files stay public for monitoring. Without the setting, behaviour is unchanged
  (localhost or trusted network, as before).
- **Health snapshots and epoch summaries** are stored as received: every numeric field, keyed by its own name and
  `parent.name`, under its calendar date. They appear in `GET /api/health/series` and on *Health*. This keeps unusual
  or changing Garmin layouts without guessing what the fields mean.

### Not verified

- The activity list, file download and callback layouts were **not run against a real Garmin account**. The paths and
  field names come from the Android implementation that was verified on 2026-11-12. A different layout yields fewer
  values, not a crash. Snapshot/epoch field names are likewise stored verbatim and marked **verify**.
- Sign-in was exercised through the app's test client, not against a browser or a reverse proxy. It is one shared
  password for one self-hosted user, not a multi-user system; keep the server on localhost or behind HTTPS.
- Nothing ran on a phone; this release changes the server only. The APK is a new build so its version matches the tag.

### What changed in the code

- `garmin/personal.py`: paginated activity list, ZIP/FIT download, summary fallback and a 30-file cap.
- `garmin/ingest.py`: `activityFiles` upserts, observation storage and counters.
- `web/routes_api.py`: allow-listed callback fetching with size and redirect guards; backfill endpoint from v0.46.0.
- `config.py` (callback hosts, password) and `web/auth.py` (new): signed session cookie.
- `web/app.py`, `web/routes_ui.py`, `templates/login.html`: login form, logout, settings status.
- `garmin/mapper.py`: `map_observation`; `web/templates/health.html`: snapshot and epoch tables.
- Version 0.47.0, versionCode 47.
