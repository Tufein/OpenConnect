## OpenConnect v0.46.0: your own Garmin key on the server, series, splits and best efforts

Five items from the roadmap in one release: the last big gap in server sync, the missing health series,
and the track-derived numbers people asked for.

### Install

Download `openconnect-v0.46.0.apk` below and open it. It installs **over v0.45.0 and keeps your data and your keys**
(same signing key). Needs Android 8.0 or newer. Check the download against `openconnect-v0.46.0.apk.sha256`.
The server is installed as before; SQLite gains a `day_series` table and needs no manual migration.

### What is new

- **Personal API on the server.** Set `OPENCONNECT_GARMIN_MODE=personal` and `GARMIN_PERSONAL_KEY` (the key you
  create on the Garmin Connect website) to pull your own daily health, sleep, HRV, Pulse Ox, respiration and Body
  Battery without a developer agreement. The key is sent only to `personal.connectapi.garmin.com`, in exchange for a
  short-lived token; the token is renewed before it expires and once on a 401. A data type Garmin has not granted is
  skipped and reported, as in live mode. **Activities are not imported in personal mode yet.**
- **Through-the-day series.** Stress and Body Battery readings from `stressDetails`, SpO2 and respiration from
  sleeps, and all-day HR when Garmin sends it are stored per day and shown as charts on *Health*. The API has
  `GET /api/health/series?day=YYYY-MM-DD`. The SVG charts now also have native hover tooltips (no JavaScript).
- **Splits and best efforts.** `GET /api/activities/{id}/splits` returns one row per completed kilometre, shown on
  the activity page. `GET /api/records/best-efforts` finds the fastest 1K, 5K and 10K in your running tracks, with
  a table on *Records*.
- **Reports mention recovery.** The offline weekly report now includes the week's HRV, SpO2 and respiration
  averages (Claude already received them in the facts).
- **More Health API types.** Blood pressure, skin temperature, VO2max and fitness age are read and appear in the
  daily summaries and on *Health*.
- **Backfill UI.** In live mode, *Settings* has a form to ask Garmin to resend a chosen data type for a number of
  days; `POST /api/garmin/backfill` does the same for scripts. Mock and personal modes report that backfill is not
  available.

### Not verified

- The Personal API was **not run against a real account from the server**. The token exchange and endpoint paths
  are the ones verified in the Android app on 2026-11-12; the tolerant JSON mapping was tested against synthetic
  payloads with the observed field names. A layout change gives fewer values, not a crash.
- Blood pressure, skin temperature and user-metric field names come from Garmin's documentation and third-party
  references, not from a live payload; they are marked **verify** in `FEATURES.md`.
- Nothing ran on a phone; this release changes the server only. The APK is a new build so its version matches the tag.
- Following Ping/Pull `callbackURL`s is still not implemented: those notifications are only counted, not fetched.
- Optional authentication is not built: the server still expects localhost or a trusted network.

### What changed in the code

- `config.py`: new `personal` Garmin mode and `GARMIN_PERSONAL_KEY`; `web/context.py` wires the new source.
- `garmin/personal.py` (new): key-to-token exchange, token caching, the six verified endpoints, tolerant leaf
  mapping and 403-per-type skipping.
- `garmin/mapper.py`: `map_series`, `map_extra_metrics`; `garmin/ingest.py`: series storage and per-type counters.
- `garmin/client.py`, `garmin/fake.py`: the new pull kinds and deterministic demo data for all of them.
- `storage/db.py`, `storage/repository.py`: `day_series` table, upsert/range/latest queries, optional tracks in
  activity listings.
- `services/records.py`: `fastest_segment`, `activity_splits`, `best_efforts`.
- `web/charts.py`: native SVG tooltips; `web/routes_api.py` and `web/routes_ui.py`: series, splits, best efforts and
  backfill endpoints and pages; templates updated.
- Version 0.46.0, versionCode 46.
