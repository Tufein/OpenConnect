## OpenConnect v0.10.0: backup, sync log and data sources

### Install

Download `openconnect-v0.10.0.apk` below and open it. It installs **over v0.9.0 and keeps your data and your keys**
(same signing key). Needs Android 8.0 or newer. Check the download against `openconnect-v0.10.0.apk.sha256`.

### What is new

- **Back up and restore.** *Settings, Back up and restore*. *Back up* writes one file (`.ocbak`, JSON compressed with
  gzip) with all activities and their tracks, daily health, sleep and the watch readings. *Restore* reads such a file and
  adds it back: the same activity, day or reading is replaced by the backup's copy, nothing is deleted, and restoring
  twice changes nothing. AI keys and the Garmin key are **never** in the file; AI reports can be written again.
  A file that is not a backup, is damaged or comes from a newer version is refused before anything is written.
- **Sync log.** *Settings, Sync log* lists the last 15 syncs (50 are kept) from the Garmin account, USB, a watch folder
  and Bluetooth: time, route, how many new items, or the reason it stopped (for example `KEY_REJECTED`, `NOT_PAIRED`).
  This is meant to make the first tests on a real watch easy to report.
- **Where your data comes from.** Activities per source (Garmin account, watch, imported files, demo) with the period,
  and the totals of days, nights and watch readings.

### What changed in the code

- `core/Backup.kt`: `Backup.write(repo)` and `Backup.restore(bytes, repo)`. The file is read and checked completely
  first, then written, so a damaged file changes nothing. Unknown extra fields are ignored so later versions can add
  data. Decompression is capped at 400 MB.
- `core/SyncLog.kt`: the log entries, capped and stored as tab separated text lines; `DataOverview.of(repo)` for the
  sources card.
- `sync/SyncLogKeeper.kt` keeps the log in one preference. `WatchController` and `GarminController` report how every
  sync ended through a new `onSynced` callback, so the log also fills during background syncs.
- Settings got three cards; the file pickers are in `MainActivity`.
- Tests: `BackupTest` (round trip, merge, twice, damaged, newer, unknown fields), `SyncLogTest`, `SyncLogKeeperTest`,
  a Garmin controller test for the log, and a Settings screen test with a screenshot.

### Honest limits

- Restoring is a merge, not a reset. To get an exact copy on a new phone, restore into a fresh install.
- The log does not yet have entries for syncs from before this version.
- The roadmap's "prefer one source when two disagree" switch is not built. Duplicates are already skipped by start time.
- The file pickers were checked in the UI test only up to the buttons; the real Android picker needs a phone.
