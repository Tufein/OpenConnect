## OpenConnect v0.2.0: the Android app

OpenConnect now has a **standalone Android app**. It needs no server and no account: your data stays in
the app's private storage on the phone. The Python server from v0.1.0 is unchanged and still included.

### Install

Download `openconnect-v0.2.0.apk` below, allow installing from your browser or file manager when
Android asks, and open it. Needs **Android 8.0 or newer**. Check the download against
`openconnect-v0.2.0.apk.sha256`.

### What the app does

- **Home, Activities, Health, Reports and Settings** screens, English and Dutch, a phosphor-green dark
  theme and a light theme that follows the system.
- **Activities** with a sport filter, route map, heart-rate and elevation charts, kilometre splits and
  export as FIT, GPX or TCX.
- **Health and weekly reports**: steps, sleep, resting heart rate, Body Battery, week totals and personal
  records.
- **Import** FIT, GPX and TCX files from the phone, or share or open a file with OpenConnect. Importing
  the same file twice does not create a duplicate.
- **Demo data** (about 45 days) to look around without any data of your own.
- **AI reports** per activity and per week. By default they are written offline by rules and nothing
  leaves the phone. With your own Anthropic API key (kept in Android Keystore-backed encrypted storage)
  they are written by Claude from a short numeric summary, never the GPS track.

### How it was built

A pure Kotlin `core` module (storage interface, FIT/GPX/TCX, statistics, reports) with 63 unit tests,
ported from the server: the exported FIT, GPX and TCX files are byte-identical to the server's. On top of
it a Jetpack Compose app with SQLite storage. 14 more tests in the app module cover formatting and
storage, and two of them run the real activity on the JVM: loading demo data, opening an activity, writing
reports and switching between every tab, in English and in Dutch.
See [docs/ANDROID.md](https://github.com/Tufein/OpenConnect/blob/main/docs/ANDROID.md).

### Known limitations

- **Garmin account sync is not in the app yet.** It needs Garmin's Personal API (your own key, Garmin's
  approval); the way in for now is file import. See docs/ANDROID.md for why the server's Garmin
  integration cannot be reused in an APK.
- **Not tried on a physical phone.** The app was built and tested on a computer (Robolectric, API 34).
  File pickers, share and open-with intents, Keystore encryption of the API key and live Claude calls have
  not been exercised on a device. Please report anything that looks wrong.
- **Signing key.** It is generated by the release workflow and kept in a private draft release, not in the
  repository, so that future versions install over this one. Back it up and consider moving it to GitHub
  secrets; see docs/ANDROID.md. Debug-signed builds (local or from pull requests) cannot be updated by this APK.
- Achievements exist in the server but not yet in the app.

### Also in this release

- The Python package is bumped to 0.2.0 with no functional changes.
- The release workflow builds and tests the APK first and publishes it with the Python wheel and sdist.
- A new Android CI workflow runs the tests, lint and a release build (debug-signed) on every change under `android/`.
