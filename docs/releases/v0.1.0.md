## OpenConnect v0.1.0: the foundation

The first release of OpenConnect, an open-source, self-hosted alternative to Garmin Connect built on
the Garmin Connect Developer Program APIs. It runs end to end on built-in demo data, with no Garmin
account or API key needed.

### Highlights

- **Activities**: list, detail, GPS route map, heart-rate and elevation charts, kilometre splits,
  personal records.
- **Daily health**: steps, intensity minutes, resting HR, sleep stages and score, stress, Body Battery.
- **Dashboard and weekly report** with 30-day trends and a previous-week comparison.
- **FIT, GPX and TCX import and export**: CRC-checked FIT, a FIT encoder validated against an
  independent decoder, XXE-safe XML parsing, idempotent re-import.
- **AI reports** per activity and per week, written by Claude (`claude-opus-5-5` by default, with
  server-side fallback on refusals) or by an offline template when no API key is set. Reports are
  cached by a hash of their inputs.
- **Local achievements** (badges) computed from your data.
- **Garmin integration**: OAuth 2.0 with PKCE, pull sync, push webhook (Starter tier is push only),
  backfill client, and an offline fake Garmin that produces Garmin-shaped data.
- **Interfaces**: web UI, JSON API with OpenAPI docs, CLI, Docker image.

### Research

[docs/FEATURES.md](docs/FEATURES.md) inventories every Garmin Connect function, marks which ones the
Developer API exposes (Health, Activity, Women's Health, Training, Courses) and which are not
available, and tracks OpenConnect's status for each.

### Quality

Developed test first: 230 unit and integration tests, about 97% line coverage, none of which need the
network. CI runs lint, format check and tests on Python 3.11 to 3.13, builds and smoke-tests the
wheel, and builds the Docker image.

### Known limitations

- **No login.** Run it on localhost or behind an authenticating reverse proxy.
- **Live Garmin access is untested against real credentials.** Endpoints and field names follow
  Garmin's public documentation and are configurable; items marked *verify* in the docs need
  confirming once credentials are granted.
- Personal API support, most Health API data types beyond the daily summaries, lap tables, Ping/Pull
  callbacks, Training and Courses publishing are not implemented yet (see the roadmap).
- OAuth tokens are stored in the SQLite file in plain text.
- Weeks and per-day activity totals use UTC day boundaries, while Garmin's daily health summaries use
  your local calendar date; around midnight an activity can land on the neighbouring day.
- Imported files and Garmin-synced activities are not de-duplicated against each other.
